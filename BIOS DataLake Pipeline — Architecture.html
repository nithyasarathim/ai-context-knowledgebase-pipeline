02

How the relationships are mapped

Three mappings turn disconnected records into one graph: ticket ↔ commit, commit ↔ files, and file ↔ file.

TICKET ↔ COMMIT
Ticket
Commit

Commit message parsed with regex to extract the ticket ID it resolves.

COMMIT ↔ FILES
Commit
Files

Changed-file list per commit, stored as a foreign-key relation to commit and ticket.

FILE ↔ FILE
File A
File B

Language parsers resolve imports, function calls, variable and reference links — 31 dependency types.

03

Where each relationship lands

Each mapping is stored in the data store best suited to how it will be queried.

PostgreSQL

relational

Tickets, commits and files as tables linked by foreign keys — the backbone lookup for "what resolved this, and what changed."

Neo4j

graph

File-to-file dependency edges from the language parsers — traversed to find every file a change actually touches.

MinIO

object storage

Raw source files held as the source of truth, referenced by row and node IDs rather than duplicated.
